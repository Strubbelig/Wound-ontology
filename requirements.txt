# Wound ontology — runtime dependencies
#
# Rebuilt 2026-08-21 from the project's actual imports (ast scan of src/, config/,
# scripts/, tests/ and notebooks/). The previous file was inverted: it omitted 11
# packages the code imports — including rdflib, torch, transformers and
# scikit-learn — and listed 16 it never imports. `pip install -r requirements.txt`
# into a clean environment therefore produced one where the project could not
# import at all, and nothing said so until the first traceback.
#
# ── The pin chain, in the order it is forced ──────────────────────────────────
# 1. torch is capped at 2.2.2 on macOS x86_64 — the last release with Intel Mac
#    wheels. Verified: `pip index versions torch` offers nothing newer here.
# 2. torch 2.2.2 is built against the NumPy 1.x C API, so numpy>=2 breaks
#    `tensor.numpy()` with "RuntimeError: Numpy is not available" and every
#    SapBERT call dies.                                        => numpy<2
# 3. transformers 5.x requires torch>=2.5 and silently DISABLES PyTorch below
#    that, reporting "AutoModel requires the PyTorch library but it was not
#    found" — which does not read as a version problem.        => transformers<5
# All three were unpinned. On Apple Silicon the whole chain can be raised at once
# (torch>=2.4 + numpy>=2 + transformers>=5); raise them together, never singly.
