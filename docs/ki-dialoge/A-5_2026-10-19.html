Here's what I found before changing anything.

`★ Insight ─────────────────────────────────────`
- The refusal isn't actually lost. `_judge_fca_proposals` ([orchestrator.py:1259](src/wound_ontology/orchestrator.py:1259)) puts every edge into exactly one of four lists: licensed, refused, synonym or open. Each entry carries its reason, and all four lists go to `fca_head_rule_<stamp>.json`. In a test run that file sits next to the test's own data directory. `p4_derive.py --skip-fca` already reads that report back, so the report is the existing record of these decisions.
- The test is out of date. It still assumes "named means committed or queued for review". Since rule 79, the queue is emptied on purpose: the code says "Nothing is left for review". So `class_hier.candidates` will always be empty, and every refused name will fail the test.
- There's a second gap the test would also hit. Concepts whose existence depends on undecided cells are held back before the head-word rule ever sees them (`skipped_uncertain`). Only their count is printed, not their names.
`─────────────────────────────────────────────────`

**My recommendation:** don't put the refusal in the store or the term dictionary. Rule 51 says the store holds evidence only. An edge verdict isn't evidence, and it isn't a decision about a term either. It's the rule applied to your rulings, which is a view. Instead:
1. `_judge_fca_proposals` keeps its verdicts on the orchestrator (`self.fca_head_rule`, plus the report path), so they don't exist only on disk.
2. `run_fca` also lists the names it held back as undecided, both in that report and on the orchestrator.
3. The test passes a name if it was committed, queued, or appears in the verdicts with a reason. It fails only if a name appears nowhere.

Step 3 means editing `tests/integration/test_pipeline.py`, and I was told another session may be working on that file.
