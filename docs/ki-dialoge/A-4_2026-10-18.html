`★ Insight ─────────────────────────────────────`
- The guard in `test_no_silent_failure.py` reads the code structure without running it. A handler passes only if its body contains a `raise` or a call such as `print`, `warn` or `append`; a bare `assert` doesn't count. When a handler catches the *expected* outcome (here: "the process is gone"), the cleanest fix is to restructure so there is no handler, and then assert the outcome directly.
- A module-wide shared fixture makes a test file into one ordered pipeline. That's efficient for live API tests, but a test run on its own then quietly starts with nothing. Checking at the start of each step that its input exists, and saying so when it doesn't, turns an unexplained `assert 0 > 0` into a clear message.
